# 包管理工具

前端开发最常用：npm、cnpm、yarn、pnpm

## npm

Node.js 的默认包管理器

版本锁定文件：package-lock.json

> npm v12 默认不自动执行**依赖包内**的 preinstall / install / postinstall / prepare 脚本；当前项目自身的生命周期脚本仍然会执行
```
简单来说，以后执行：

npm install

默认不会再自动运行依赖中的：

preinstall
install
postinstall
prepare

等脚本
```


## cnpm

是淘宝镜像的命令行工具，用于加速安装依赖包。

```
npm install -g cnpm --registry=https://registry.npmmirror.com
```


## yarn

Meta（原 Facebook）开源的包管理器。

版本锁定文件：`yarn.lock`;

配置文件： `yarnrc.yml`;

> yarn v4 默认不自动执行**依赖包内**的 postinstall 等生命周期脚本；当前项目/工作区自身的生命周期脚本仍然会执行

## pnpm

基于内容寻址存储，结合硬链接+符号链接，复用包文件，节省磁盘空间、安装速度快；默认非扁平化 node_modules 结构，天然阻断幽灵依赖，代码里不能导入未在 package.json 声明的依赖（如果打开 `shamefully-hoist=true` ，pnpm 会把一部分依赖提升到顶层，就和 npm/yarn 扁平模式一样，幽灵依赖又能正常导入了）



```
npm install -g pnpm
```

版本锁定文件：pnpm-lock.yaml

> pnpm v10 默认**不自动执行依赖包内**的 preinstall / install / postinstall 等生命周期脚本；当前项目自身的生命周期脚本仍然会执行。


https://pnpm.io/zh/pnpm-cli

## .npmrc

npm、pnpm 会读取项目 `.npmrc`, cnpm 仅识别少量字段

| 配置项 | 作用 | 支持工具 |
| ---- | ---- | ---- |
| registry | 设置包源地址 | npm / pnpm / cnpm |
| proxy / https-proxy | 网络代理 | npm / pnpm / cnpm |
| strict-ssl | 是否校验 SSL 证书 | npm / pnpm |
| allow-scripts | npm 脚本白名单（v12+）：默认拦截第三方依赖生命周期脚本，仅名单内的包允许执行脚本，项目自身脚本不受限制 | npm |
| ignore-scripts | 全局禁用所有生命周期脚本（包含依赖包以及项目自身脚本） | npm / pnpm |
| allow-builds[] | pnpm 编译脚本白名单（v10+）：默认拦截第三方依赖生命周期脚本，仅名单内的包允许执行构建脚本，项目自身脚本不受限制 | pnpm |
| shamefully-hoist | 开启扁平化 node_modules，允许幽灵依赖，丢失 pnpm 依赖校验优势 | pnpm |
| save-exact | 保存精确版本号，版本号不带 ^ 符号 | npm / pnpm |
| _authToken | 私有源登录令牌，不要提交到 Git 仓库 | npm / pnpm |


## npx

npm 5.2.0 版本之后内置的命令行工具。

可以直接执行包的命令，**不需要提前全局安装**：既可以运行项目 node_modules 内已安装的包命令，也能自动临时下载远程包执行，执行完毕后自动清理。

> 备注：npm v7+ 中 `npx` 是 `npm exec` 的别名；加上 `--no-install` 参数时，只会调用本地已安装的包命令，找不到就报错，不会自动下载远程包。

> npx 只能执行包在 `package.json` 的 `bin` 字段声明的可执行命令（安装后放在 `node_modules/.bin`），**不能直接执行 package.json 中 scripts 脚本**。
